# CSI prototype protocol v1 (locked shared contract)

Purpose: two ESP32-S3 boards, serial CSI capture, local-only live/record/replay UI; **not** a fall detector. No synthetic data in live mode. Numeric fields little-endian. UART 921600 8N1; receiver serial is the only capture/control port. Host must never automatically open a port. Firmware CSI source must be the separately verified transmitter MAC, not a guessed tty mapping.

## Binary serial frame

`43 53 49 31` ASCII `CSI1` magic (4), version `01` (1), type (1), payload length uint16 (2), payload (0..512), CRC32 IEEE/zlib uint32 (4), computed over magic through payload. Parser scans magic, rejects wrong version/type/length/CRC, advances one byte on rejected candidate, retains partial frames, bounds buffer to 524 + 3 bytes. Unknown types invalid. Length includes neither header nor CRC. Golden empty status-like framing is disallowed (status has fixed length). Firmware-to-host frame types `1` CSI, `2` STATS, `4` ACK; host-to-firmware `3` COMMAND. Payload length >512 invalid. At 100 Hz and 128 CSI bytes: (8+30+128+4)*100 = 17000 bytes/s before UART encoding, below 921600 baud / 10 = 92160 bytes/s; actual CSI length and rate measured, not guaranteed. CSI raw maximum 384 bytes; oversize callback increments explicit drop count.

CSI payload type 1 fixed prefix 30 bytes (`<6s6sIQHBBbB`), followed by `csi_len` raw signed int8 values: source MAC 6, receiver MAC 6, **receiver callback sequence** uint32 4, receiver boot-relative capture microseconds uint64 8, CSI byte length uint16 2, `first_word_invalid` uint8 1 (0/1), LTF type uint8 1 (**0 means unknown**; not a 64-bin promise), RSSI int8 1 dBm, channel uint8 1. `rx_seq` increments once per callback, including callbacks dropped from queue; TX packet sequence **unknown** unless independently correlated; never display RX sequence as TX sequence. Raw CSI bytes are signed imag,real pairs, zero-based pair index; select only complete pairs; when `first_word_invalid=1`, exclude first two pairs (first 4 bytes). No claim that pair index maps to physical subcarrier without validated LTF layout. Reject odd CSI length, invalid flag, malformed length and unverified source. RX identity and expected source are configuration, initially unverified until hardware identity check. RX clock resets/wraps are not host clocks.

STATS payload type 2 (`<6sIIIIII`, 30 bytes): RX MAC, callback count, accepted/enqueued count, queue_full drops, oversize drops, serial_write_fail frames, source_filtered callbacks, each uint32. Counters wrap modulo 2^32; source_filtered never enters CSI frame stream. RX heartbeat 1 Hz while serial active. RX stale threshold 2 s after last valid CSI; opened serial with stale CSI != disconnected serial. Missing stats is unknown, not zero. Host also separately counts parser invalid frames, host-source rejections, host-record drops, and observed receiver-sequence gaps (do not double count firmware queue drops).

COMMAND type 3 (`<IBHB`, 8 bytes): command id uint32 (host monotonic session-local), action uint8 (1 identify, 2 FALL_DETECTED, 3 FALL_CONFIRMED, 4 reset), TTL uint16 milliseconds (1..2000), source tag uint8 **1=manual_test only**. Firmware validates all fields, starts TTL from receipt with monotonic clock, bounds it by 2000 ms, and resets indication at expiry; reset cancels immediately. Commands cannot originate from CSI motion or replay. No output GPIO enabled by default; firmware returns `UNAVAILABLE` until verified wiring/pins and a deliberate build-time mapping enable. ACK type 4 (`<IB`, 5 bytes) echoes id and status: 0 applied, 1 malformed, 2 unavailable, 3 invalid action/tag/TTL. ACK means firmware accepted/processed request, **not physical observation**. Host records desired, ACK, human-observed indication separately. Host command expiry cannot be renewed automatically; manual action only. GPIO45/46/47 proposed discrete; GPIO48 proposed addressable RGB; all remain disabled until verified board wiring, strapping and actual ESP32-S3 GPIO46 documentation. No silent substitutions.

## Browser contract v1

One Python server bound to `127.0.0.1:8765` by default, static UI and JSON API + `/ws`. All mutations require same-origin `Origin` (or no Origin for local CLI), localhost peer, JSON input validation; no remote bind by default. `/api/state` GET snapshot, `/api/ports` GET discovery only (never opens), `/api/connect` POST `{port,baud:921600,source_mac,rx_mac,identities_verified:false|true}` (requires `true` explicitly only after human mapping), `/api/disconnect` POST `{}`, `/api/record/start` POST `{name,notes}`, `/api/record/stop` POST `{}`, `/api/marker` POST `{kind:"motion_start"|"motion_stop"|"note",note?}`, `/api/replay/start` POST `{name}`, `/api/replay/stop` POST `{}`, `/api/command` POST `{action:"identify"|"FALL_DETECTED"|"FALL_CONFIRMED"|"reset",ttl_ms:1..2000,source:"manual_test"}`. JSON response `{ok:true,...}` or `{ok:false,error:string}` with appropriate HTTP status. Recording names `[A-Za-z0-9_-]{1,64}`, safe within data/recordings; never use arbitrary path. Commands require real opened verified receiver, no replay/test. No TX serial control unless independently verified second port; TX health inferred only from RX source and accepted CSI, never claimed as independently verified.

`/ws` sends JSON snapshots `{type:"state",state:{...}}` at <=10 Hz; snapshots include `mode` LIVE/REPLAY/TEST, `connection` disconnected/open, `source_verified`, `rx_mac`, `source_mac`, `rx_rate_hz`, `last_sample_age_ms` (null if none), `csi_health` UNKNOWN/OK/STALE, `stats`, `frame_errors`, `sequence_gaps`, `selected_pair`, `trace` last <=300 points `[{t_ms,real,imag,valid,gap}]` (no smoothing, signed int8 units), `variation` `{value,unit:"CSI signed-LSB stddev",window_ms:1000,valid_samples}`, `recording`, `command` `{desired,ack,physical_observation:"unverified"}`, and `events` recent bounded log. Variation is population standard deviation of signed real components of selected valid pair within trailing 1000 ms of receiver capture time; fewer than two samples or stale => null/UNKNOWN, never zero/fall probability. Gaps retain explicit `gap:true`; replay preserves recorded timing/markers. UI may downsample trace only; recorder writes every accepted raw binary serial frame plus host monotonic and wall arrival clocks.

Recording format JSON Lines: first `meta` line with version, expected identities, verified flag, notes, start host wall/monotonic; each `frame` line includes base64 exact raw serial frame, arrival `wall_ns` and `mono_ns`; marker lines include kind,note, wall_ns,mono_ns and latest RX capture timestamp (if available); `end` line with counts. Flush and close on stop/disconnect/shutdown; recordings opened exclusively (`x`), never overwritten. Replay uses same parser/processor as live, never touches serial and cannot send commands, preserves gaps/timing without pretending hardware is present. Opt-in TEST mode, if implemented, explicitly labels fixtures SIMULATED and cannot send hardware commands.
